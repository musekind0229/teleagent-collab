Task (刀I): make TeleAgent-native PERMISSION decisions reachable through the Application API, minimal change.

Root cause found live (TeleAgent desktop 2.6.0, Go server super-agent-code):
- win_collab/core.py creates each session with permission [{"permission":"*","pattern":"*","action":"ask"}] and the server echoes it back, but the effective ruleset is dominated by the agent-level rules of `opencowork-default` (GET /config -> agent.opencowork-default.permission: powershell=allow, question=allow, bash=deny, external_directory {"*":"ask", ...}); in-workspace read/write/edit/powershell execute without any permission request. There is no yolo/auto-allow mode in use (no "[permission] auto-allow" log lines).
- The only thing that still asks is `external_directory` (touching a path outside the workspace). Those requests DO arrive (seen live: a mistyped outside path produced a permission request), but `hard_reject()` rejects every external path not pinned in `charter.external_inputs`, and the Application API currently has NO way to pass `external_inputs`, so via the API a permission decision can never be produced.

Implement:
1. `src/framework/app_service.py`: accept an optional Goal field `external_inputs` (list, max 8, each exactly {"path": <absolute path str>, "sha256": <64 hex>}) — validate shape like `project_forbidden_tools` does (raise AppError code "invalid_external_inputs"), store it with the goal the same way `forbidden_tools` is stored (look at how forbidden_tools is accepted in submit/normalize and in contracts/goal.schema.json — update the schema too if goals are validated against it), and pass it through in `worker_charter_for_task` as `charter["external_inputs"]`. `WindowsSupervisedExecutionBackend._charter` already passes `external_inputs` through; win_collab `validate_charter` does the deep checks (file inside repo, sha matches) — keep that as the authority. Backends that don't use it (antigravity/inprocess) must ignore it harmlessly.
2. `bin/hermes-collab-request.py open`: add repeatable `--external-input PATH`; the client resolves the absolute path, computes sha256 of the file and sends `external_inputs: [{"path","sha256"}]`. Error cleanly (code "bad_external_input", exit 1) if the file doesn't exist. Don't change default output encoding.
