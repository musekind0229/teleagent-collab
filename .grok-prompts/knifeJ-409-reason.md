Task (刀J): when a decision POST is refused by the worker controller, the HTTP 409 must say WHY.

Observed live: POST /v1/requests/{goal}/decisions/{dec} {"verdict":"pass"} on a contaminated artifact review returns
  409 {"ok": false, "code": "worker_decision_failed", "error": "worker decision failed: ValueError"}
The real reason (raised in win_collab/core.py Engine.decide, review pass branch: 'Artifact content contaminated (AIGC mark / invisible chars): CONTAMINATED label.txt: AI生成x1') is swallowed by `CollabApplication.resolve` in src/framework/app_service.py (`except Exception as e: raise AppError(f"worker decision failed: {type(e).__name__}", ...)`).

1. win_collab/core.py: add `class ArtifactContaminatedError(ValueError)` carrying `.summary` (the summarize() line) and `.findings` ({name: scan dict}); raise it in the review pass branch instead of plain ValueError (message unchanged in spirit). Other `raise ValueError(...)` messages in Engine.decide are controller-authored fixed strings with no secrets — leave them as ValueError.

Fail this review so the worker can redo it, or re-open the request with acceptance.allow_aigc_marks=true if the marks are intended." and include structured fields in the JSON body: "contamination": {name: {aigc_marks, invisible, encoding}} (counts only, no content), "hint": "allow_aigc_marks".
