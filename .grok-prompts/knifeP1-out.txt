**Fix.** On dispatch, `AppCoordinator` binds `workspace` to `workspaces_root / goal_id / task_id` — the directory passed to `start_run` — through `bind_task_run`. Handoff uses that stored value. A backend `result.workspace` that differs is ignored, and the trusted directory is used (covered by test). Binding a second, different directory returns `workspace_binding_conflict` and does not retarget. `_workspace_root` and the containment checks are unchanged: path traversal, symlinks, credential-like files, out-of-workspace files, name collisions, and unaccepted artifacts are still rejected. An Antigravity artifact path outside the trusted workspace is still refused, and the successor is not started.

Legacy task records with no `workspace` are recovered only by recomputing that same scheduler path, and only when the directory exists, is a real directory, and matches. Otherwise handoff fails with `dependency workspace unrecoverable: ...` and the task is not redispatched. Windows and Linux supervised runs share this path: their UUID job directory stays the worker root, declared outputs are mirrored back into the scheduler directory, and the finished result is stamped with the trusted workspace.
