# Registered runtime and bounded repository inventory

Production startup uses the one operator-registered checkout on the authorized integration branch. The registration is local machine state outside Git. Windows resolves LocalAppData through the OS API, not caller-provided environment variables. There is no production bypass CLI switch or environment flag.

Startup verifies the physical checkout root, branch, clean tracked index/worktree, absence of untracked source files and exact HEAD equality with the authorized GitHub branch tip. The GitHub ref is retrieved over certificate-verified HTTPS from a fixed api.github.com host without credentials, proxy lookup, redirects, fallback, URL rewriting or account-pool access. Missing registration, wrong root/branch, dirty source, unpublished HEAD or network/response uncertainty refuses startup. The exact-tip requirement is deliberately stronger than merely being an old GitHub ancestor. Rate limiting or a private/unavailable API ref is a refusal, not permission to use cached evidence.

All existing bin CLI mains share the gate. The goal-entry service checks before acquiring/writing state or backing up/restarting an existing host, then the service constructor revalidates. HOLD-to-release revalidates again. No new production execution entry is introduced. Goal-entry read-only owner/result operations keep the existing same-store path; this does not permit starting an unregistered host. Direct arbitrary Python code is not an OS sandbox boundary. Existing in-process synthetic test factories and explicit unit-test injection are not exposed as production CLI flags, and test audit guards forbid model/network side effects.

An existing state may remain outside the registered checkout using the established explicit existing-state, settled identity, exact store digest, disjoint backup and host-owner/persist locks. Source registration does not migrate state, clear old results or usage, authorize a continuation, release models or waive no-verdict stop-loss. The actual owner must verify the live state binding and retain its failed attempts, resources and artifacts. Do not freeze active state or its writable ancestry merely because its old source checkout is archived.

The metadata-only inventory is available as:

    PYTHONPATH=src python -B -m framework.repository_inventory --root ENGINEERING_PROJECT_RECORDS --output LOCAL_REPORT_JSON

It distinguishes a .git directory with a readable HEAD framework tree plus a checked-out framework directory, a worktree .git file, other Git directories and bare object archives. The three current-layout file markers are now a separate diagnostic count: they miss older layouts and can falsely match an uncommitted overlay without a corresponding HEAD tree. The broad source-copy definition matches the historical baseline; it is not whole-Git integrity certification. It does not read Git configs, credentials, source contents, state bodies or raw logs. Reparse/symlink paths and named state/raw/workspace/cache/backup/baseline/private trees are excluded; scan errors and the exact excluded scope are reported. An all-.git candidate count is not a full-source-repository count. Keep one stable bounded definition for daily comparison and report exclusions instead of presenting a partial scope as a whole-machine total. New repairs use this repository's branches/worktrees, not complete repository copies.

Old-copy freezing is a separate coordinated local operation. A Windows ReadOnly attribute is not an OS write-protection claim; a Python source file's execute ACL does not prevent an interpreter from reading it. Old unmodified code cannot gain the new startup gate retroactively. A freeze requires a reviewed finite path list, preserved dirty/index/untracked files, a verified rollback and state-continuation plan, no other writers and tested read-only enforcement for that selected source scope. No broad recursive ACL, private profile change, deletion, model invocation, GitHub push, main merge or deployment is performed by this feature.

The synthetic tests exercise positive and negative registration/remote evidence, HTTP refusal without redirects or auth, environment overrides not bypassing registration, all existing CLI guard coverage, rejection before state creation and inventory classification. GitHub publication and the next authorized real goal's runtime_root/HEAD remain final operator acceptance checks, not conclusions from mocks.
