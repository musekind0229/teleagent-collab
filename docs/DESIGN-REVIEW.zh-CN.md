# teleagent-collab 设计与实现评审

评审基线：GitHub `musekind0229/teleagent-collab` 的 `aa6a9b4`（2026-09-07 拉取）。
本地适配分支：`windows-codex-lead`。以下原版行号指该基线；此分支保留原版 `src/` 以便核对。

## 判断

职责分离、统一章程、事件触发审批、可替换组长、记忆与施工分仓，方向合理。
但当前代码是多轮实验拼接的原型，不能把烟测通过理解成无人值守验收闭环已经可靠。
优先统一执行状态机和权限/验收路径，再扩展工人数量；不需要先换工作流平台。

## 架构层应澄清的边界

- **工作目录不是沙箱。** 原版 Python 目录检查与模型审批只覆盖可观察的请求，不等于限制 TeleAgent 和其子进程的实际写盘、凭据、网络。要满足最初宪法，仍需验证 TeleAgent 原生运行时限制，或放进独立 Windows 用户/VM 等边界；不能用 prompt 代替。
- **规则审批与语义验收分开。** `run-evidence.txt` 是工人自述材料；命令/输出应由基础设施观察，关键测试由组长独立复核，验收绑定具体版本。
- **永久禁止列表并非权限模型。** 原版包含粗糙凭据特征和白名单；合法配置任务应靠明确授权实现，不能通过某个文件名是否含 token 决定全部行为。
- **扫描批次不等于合并模型调用。** 原版每条仍同步调用组长，一次慢调用会阻塞其他审批。新入口将待决请求落队列，由独立组长消费，扫描不等待模型返回。
- **已有 Grok 聊天回报只作为线索。** 实际代码、报告与运行证据优先；尤其原版并行烟测是模拟路径，不证明真实并行验收成立。

## Windows 适配策略

保留原仓，新增 `win_collab/` 作为统一执行入口；不继续修补三份相互分叉的实验脚本。
当前对话可作为组长，通过 `inbox` 获取请求，用 `decide` 提交绑定 request/context 的决定。
可选 `lead.py` 提供 Codex CLI / 中立 JSON 命令适配器。Codex CLI 是独立执行实例，不继承当前对话记忆，不能冒充“当前这个我”。

已实现：SQLite 状态与事件、最多三路会话、独立目录、仅处理自有 session、严格决定绑定、全部产物哈希、API 工具结果摘要、重做预算/总时限、不确定启动防重复派工、取消/超时 abort、PowerShell 入口。

实际边界：状态和工人仍可能属于同一 Windows 用户，尚不具备抵抗恶意工人修改控制器的 OS 隔离；abort 回应也不证明所有子进程都已停止。进程崩溃后遇到不确定启动会停止并要求核对，而非宣称 exactly-once 自动恢复。当前支持三槽调度不代表已验证 TeleAgent 的账号侧并发上限。请求次数预算不是精确 token/积分预算。

本机版本：TeleAgent 界面 2.4.1；首次发现 API 为 127.0.0.1:4397；401 表明需要 local-v1 认证。运行时没有保留原 Linux 脚本依赖的三个环境变量。真实接入与验收结果见后续本地验证记录，不能用模拟测试代替。

Codex 接入依据：本机 `codex exec --help`，以及 [官方非交互模式文档](https://developers.openai.com/codex/noninteractive)。使用 read-only、结构化输出，禁止绕过审批/沙箱参数。
