## 3. Focus audits（代码结论）

### A. Approval-channel failure → business rework？

**已满足。**

- `closed_loop.artifact_review`：binding/protocol → `error_class=decision_channel_failed`（注释：caller must not rework worker）。
- `run_inprocess_closed_loop`：`if review.get("error_class") == "decision_channel_failed":` → stop；**不**调用 `budget.consume_rework()`；note：`decision_channel_failed → stop; rework budget not consumed`。
- `lifecycle.DECISION_CHANNEL_LEAD_CODES` / `map_error_class` 将 timeout、illegal_json、application_id_mismatch 等归为 `decision_channel_failed`。
- 测试：`test_framework_b8.test_channel_fail_does_not_consume_rework`、`test_channel_timeout_not_business_rework`（`reworks_used==0`，`rework_used_new_run==False`）。
- 对比：`acceptance_failed` 才 `consume_rework()` 并开新 Run。

### B. Permission translation dropping auth / missing→allow？

**需修正（小）：native 丢字段；「缺→allow」本身已满足。**

已满足部分：

- `to_public_permission`：缺失 → `""`，不是 allow。
- `run_observe`：不可用 status → `activity=unknown`；不发明 `finish_successful`。
- `charter_map`：缺 `allow_*` 省略并 warning，不填通配。
- `hard_rule_decision`：空 allowlist 对 secret → reject；非 secret → `None`（交 lead），glue/scheduler **无** unconditional once。
- 实测：`permission=""` 不会变成 allow。

需修正：

- `native` 仅复制固定键；实测 raw 中 `scope`/`mode`/`allowed`/`action` 被丢弃。相对 §9「保留原始证据引用、所有目标与动作参数」属信息丢失。建议 `native=dict(raw)` 或至少保留未识别键（不把未知映射为放行）。

### C. Plan revision overstepping authorization（contract vs plan）？

**需修正。**

已满足：

- 过期/错误 coordinator 拒绝；plan 不能改写 ownership 字段；不能 drop active task；非法 lifecycle 拒绝（`test_framework_b12`）。

缺口（实测）：

```text
validate_plan_revision({..., "budget": {"wall_sec": 1e9}, ...}) → (True, "ready")
validate_plan_revision({tasks:[{..., "inputs":{"allow_paths":["/**"]}}]}) → (True, "ready")
```

`validate_plan_revision` 不绑定 Goal 合同边界（budget / allow_* / acceptance 降标）。合同修订与计划修订未在内核分离强制。外科补丁方向：禁止 plan 顶层 `budget`/`boundaries`/`allow_*`，或相对 Goal 合同做「只收紧不放宽」校验；扩大授权走合同修订入口（可先 `unsupported`）。

### D. Budget accounting-only without reserve before dispatch？

**已满足。**

- 模块头注释：`Dispatch reserves; finish reconciles`。
- `GoalBudget.reserve` / `can_reserve`；`committed = consumed + reserved`。
- `can_enter_running`：deps → occupancy → **`budget.can_reserve`** 后才 ready。
- 调度模拟路径在进 running 前 reserve。
- 测试：`test_reserve_reconcile_releases_unused`、`test_over_budget_reserve_denied`、`test_over_budget_does_not_report_success`。
- 返工/新 id 不重置账户：`test_minting_new_id_does_not_reset`。

### E. Cancel/unknown releasing resource locks too early？

**已满足。**

- `cancel_goal` 只改 Goal/Task 状态为 `cancel_requested`，**不**调用 `workdir_claim.release`。
- `effect_cancel` 同样不碰 claim。
- Claim 仅由 holder `release` / `force_release`，或 `run_job_wire`/`run_claimed_inprocess_job` 的 `finally`（工作结束后）。
- Task `unknown` 状态存在于 lifecycle，但无「进入 unknown → 自动放锁」路径。
- `cancel_requested ≠ cancelled` 有测试覆盖。

附注：durable cancel 与 workdir claim **尚未联接**；因此取消不会过早放锁，也不会在 cancel 路径上显式「确认停止后再放锁」。symlink 别名锁范围：依赖 `Path.resolve()`，**无**专用 symlink 单测 → 记为附带 未验证，不单开需修正项。
